# 系统与剧本接口

本版是独立系统样机。剧情正文可以在后续讨论中替换，不需要重新制作地图、背包、存档或战役界面。

## 文件职责

| 文件 | 内容 |
|---|---|
| config.js | 战区、道路、初始能力、兵粮、难度参数、装备、指令参数、事件池 |
| engine.js | 合法动作、统一结算、战斗、外交、连通、寿命、胜负和存档校验 |
| app.js / index.html / styles.css | 页面展示、用户操作、浏览器自动存档及导入导出 |
| policy.cjs | 可复现的公开信息策略代理，不读取游戏未来随机数 |
| simulate.cjs / engine.test.cjs | 难度模拟与规则测试 |

## 可以直接替换的剧本内容

`config.events.definitions` 中每个事件含标题、短文、选项列表。选项有 `id`、`label`、`description` 和 `success`；概率选项另有 `probability` 与 `failure`。可见说明中的 `{probability}` 由引擎填入当时成功率。

`config.events.pools` 分为 `domestic`、`march`、`battle` 三个池，使用事件 id 和权重。不存在固定章节或年份强制排程。现在每回合只出现一个简短机制事件，供验证指令和风险使用。

效果可涉及当前健康、兵力、军粮、国库、机缘、永久能力、内部支持、东吴关系以及当前战役敌兵/敌粮。游戏代码仅解释明确支持的效果字段，不执行事件中的代码。增加新效果种类时，应同时在引擎和测试中定义其含义；不能只把新字段写进正文就认为它已经生效。

有限机缘由 `finiteOpportunities` 和存档中的已用记录约束。地区机缘按地区的 `chance` 与永久首次占领记录发放。换成新事件时仍须保留“同一奖励不能反复取得”的约束。

装备配置描述类别、效果和说明。个人装备只进入前两个槽，军政装备只进入后两个槽；效果直接影响有效值或后续结算，不通过穿脱改写当前资源。

## 运行时接口

浏览器加载配置后获得 `window.BeifaEngine`；Node.js 可直接 `require('./engine.js')`。

```js
const game = new BeifaEngine({ difficulty: 'normal', seed: 123 });
const view = game.getView();
const action = view.actions.find(item => item.allowed);
game.act(action.action);               // 锁定事件，尚未结算回合
game.choose(game.getView().event.choices[0].id); // 统一结算一次
const restored = BeifaEngine.deserialize(game.serialize());
```

界面消费 `getView()` 的快照、合法动作、战术预览和事件选项；动作提交必须通过 `act`、`choose`、`spendChance`、`equip`、`unequip` 等方法。非法调用会回滚，包含随机数状态，不得直接修改运行时状态来实现一般游戏操作。

存档使用独立的 `beifa-simulator` 格式，保存配置版本、随机数状态、待选事件、地区归属与敌军残余、外交状态、预警和冷却、装备以及永久奖励/胜利记录。浏览器键名为 `beifa.system.v1`。大改配置结构或地区/事件 id 时应提升配置版本并提供迁移，避免旧存档被新内容错误解释。

## 难度报告的解释

策略代理使用固定的公开资源阈值、可见战术预览和独立随机流。`casual` 是有推进意图的加权随机选择，不是所有按钮等概率；`novice` 是固定的补给与路线规则；吴先行、全图、治疗和能力策略用于比较机制价值。

留出种子区间与调参区间分开。不同策略可使用同一个种子区间进行成对比较，每个单元内部各局使用不同种子。报告中的区间是固定代理的统计区间，不能解释成真实新手的通关率。回合数也不是实际分钟数，后续需要玩家试玩验证阅读与决策时间。
